# 05. 项目复盘：最难问题、学习收获与下一步演进

## 1. 实际投入用时与完成度盘点
- **总投入用时**：约 2.5 小时（在建议的 3 小时预算内完成全部核心链路、4 组场景 Trace 与自动化测试）。
- **完成部分**：100% 完成核心 ReAct 决策引擎、5 个领域工具、4 类必测边界场景（正常修正复检、资料缺失拒绝编造、工具超时降级恢复、步数上限熔断）及全套文档。
- **未完成/精简部分**：未开发图形化 Web UI 界面，未接入真实向量数据库（当前基于关键词匹配得分检索 JSON 文档库）。

## 2. 遇到的最难问题与解决过程
**最难问题：如何在保证 ReAct 灵活性的同时，100% 杜绝模型“带病交付”（即在未通过时长/合规复检或步数耗尽时错误返回成功状态）？**
- **问题分析**：在自由工具调用循环中，模型很容易在修改完草稿后“自信地认为已经改好了”，从而直接调用结束动作输出脚本，或者在步数即将耗尽时把半成品草稿当作最终结果返回。
- **解决方案**：我们采用了 **“软决策（Model Policy）+ 硬护栏（State-Lock Guardrail）”** 的混合架构：
  1. 将草稿视为不可变版本序列（`v1 -> v2 -> ...`），每次修改必须递增 `version`；
  2. 工具检验结果与草稿 `version` 严格绑定，任何未经 `estimate_script_duration` 和 `check_script_compliance` 标记为当前版本通过的草稿，在状态机层面无法触发 `FINISH_COMPLETED`；
  3. 当 `while` 循环因触及 `max_steps` 或 `max_tool_calls` 退出时，统一落入底部的熔断兜底分支，强制将状态标记为 `incomplete_step_limit`，将 `compliance_status` 标记为 `UNVERIFIED_AT_STEP_LIMIT`，确保绝不向业务下游泄露未经验证的脚本。

## 3. 核心学习收获
1. **生成式 Agent 中“验证工具（Verifier Tools）”与“生成动作”同等重要**：短视频脚本属于强约束创意生成任务，把模糊的自然语言约束（如“大概 30 秒”、“别用违禁词”）转化为确定性的计算工具（字数语速模型、规则引擎），通过工具返回的量化差值（如“超出 13.0s，需压缩至 92~132 字”）反哺模型修正，比单纯写复杂的 System Prompt 有效得多。
2. **可观测性（Traceability）是调试与评估 Agent 的基石**：通过规范化记录每一步的 `tool_params`、`observation_summary` 与 `decision_rationale`，能够瞬间定位模型是在“检索阶段漏读了文档”还是在“修正阶段未遵循字数预算”。

## 4. 下一步演进计划
1. **引入 TTS 真实语音合成时长测量**：将当前基于字数的线性时长估算升级为轻量级 TTS 预合成（如 Kokoro / MeloTTS），直接提取音频波形时长与语调停顿，实现毫秒级分镜对齐。
2. **多模态分镜画面可行性校验**：结合小影科技的视频素材库检索工具，在生成分镜画面描述（`visual_description`）时自动检索现有视频素材片段库，评估每个分镜是“可直接复用现有素材”还是“需实拍/AIGC 生成”，进一步打通从脚本到成片剪辑的自动化链路。
